# Evaluation protocol (desensitised)

Scope: every change on the generation side - model swap, prompt/persona edit, fallback
rule, sampling parameter, fine-tune. The protocol decides what may be called an
improvement. It is deliberately boring: only fixed inputs, exact counters and human
ratings count as evidence.

Numbers quoted here come from the project this repo was extracted from; the ones that
can be reproduced inside this repo are marked in `docs/results.md`.

## 1. Why a protocol at all

Three failures, in order, each cheaper to prevent than to discover:

| What happened | What it taught |
|---|---|
| Style metrics at 100% while replies answered the wrong question | Any single family of metrics can be satisfied by generic filler |
| The same unmodified configuration scoring 30.6–72.2% on one metric across runs (n=36) | Run-to-run spread can exceed the effect being measured |
| A metric that had silently been broken for weeks ("at most one question per reply") | An all-green dashboard on a broken metric is worse than no dashboard |

Therefore: fixed inputs, discrete counts, human ratings - and every metric treated as
code under test, with at least one negative case.

## 2. Layer 1 - fixed inputs

- 12 scenarios / 40 turns. Real logged conversations are preferred; invented scenarios
  only cover failure modes the logs did not contain.
- Each scenario is a *turn sequence*, not a single prompt: several failure modes
  (repeating itself, dropping an earlier agreement, ignoring a constraint) only appear
  from turn 2 onwards.
- Every scenario states which failure mode it is there to expose. If a scenario has no
  judgeable failure mode, it stays out of the automatic counters and goes to the human
  sheet only - otherwise it just adds variance.

## 3. Layer 2 - deterministic counters

| Counter | Definition | Expected |
|---|---|---|
| Fragment | unbalanced quotes/brackets, a sentence starting with a closing mark, trailing dangling punctuation, empty text | 0 |
| Repetition | sentence-level similarity ≥ 0.80 against the last three replies (difflib on punctuation-stripped text) | 0 |
| Question cap | more than one question mark in the reply | 0 |
| Sentence cap | more than 4 sentences | 0 |
| Imperative/prescriptive pattern | an unrequested directive ("you should…", "first step…") | 0 |
| Number leakage | any number shape in generator output (numbers may only come from the verified-text module) | **must be 0** |
| Foreign-script leakage | a Latin word inside an otherwise CJK reply | 0 |
| Verbatim restatement | reply opens by restating the user's words | lower is better |
| Missing directive | user explicitly asked for a concrete suggestion and the reply has none | lower is better |

The last two are approximations, not truth: they are phrase tables plus a small cue
detector. Judging the *wrong* direction is more dangerous than not judging at all, so
every run also samples raw replies by hand (at least 10 per change).

## 4. Layer 3 - human ratings

- Sheet generated by the same script that ran the counters, so both layers cover
  identical items.
- 5 dimensions, 1–5, plus a hard-defect checkbox. Two raters, independently, no
  averaging before the agreement check.
- Report: overall mean, hard-defect count, per-dimension agreement, and Cohen's kappa.
- **Gate: kappa < 0.4 → the evaluation is unusable.** Fix the criteria first
  (10-item pilot → discuss disagreements → revise), then re-run. Do not average a
  low-agreement result into a confident-looking mean.

## 5. Decision rules

1. **Safety items never regress.** Zero number leakage, zero empty replies, protected
   turns never handed to the generator. One violation disqualifies the whole run;
   better numbers elsewhere do not compensate.
2. **Paired, not resampled.** Comparing two post-processing rules means replaying one
   frozen dump of raw output through both. Two separately sampled runs produce
   differences that are mostly noise (see §1).
3. **±5 points is noise** at n≈76. To claim a smaller difference, add samples or use
   the human sheet. To claim a larger one, still show it on paired data.
4. **Same task set.** "It got better" on a different prompt set is not a comparison.
5. **State the sample size** next to every rate, and the label source (human / model /
   rule) next to every accuracy.

## 6. What the automatic counters cannot see

- Fabricated detail (inventing something the user never said).
- Misattributed emotion (reply opens with the wrong feeling).
- Answers that ignore the earlier context (a nickname or a time mentioned two turns
  ago).
- Boundary crossings (diagnosing, promising what the system cannot do, inventing
  contact details).

These go to the human sheet, and the protocol says so explicitly instead of pretending
the counters cover them.

## 7. Re-running

```bash
python -m pytest -q                    # rule-level regression (this repo)
python -m src.offline_test --rounds 1  # isolation + routing constraints
python -m src.verify_onnx --demo       # export consistency, reporting path
```

For a generation-side change, the sequence is: replay the frozen dump → counters →
generate the human sheets → two raters → agreement check → only then look at the
numbers side by side.
